# Premium Consulting Frontend Flow

## 목적
유료 사용자 전용 `연속 상담 스레드` 기능을 프론트 화면에서 어떻게 노출하고 동작시킬지 정의한다.

이 문서는 MVP 기준 화면 플로우와 UI 상태를 정리한다.

## 제품 개념
연속 상담은 `같은 흐름의 상담을 이어서 질문하는 기능`이다.

중요한 전제는 아래와 같다.

1. 기본 상담은 항상 `새 상담`
2. 연속 상담은 유료 사용자만 사용 가능
3. 같은 스레드 안에서만 이전 질문/답변을 이어서 사용
4. 다른 종목이나 다른 고민이면 새 상담을 권장

## 주요 사용자 시나리오

### 시나리오 1. 무료 사용자가 상담 시작
1. 사용자가 상담 시작 화면 진입
2. `새 상담 시작`만 노출
3. 연속 상담 관련 UI는 숨기거나 잠금 표시

### 시나리오 2. 유료 사용자가 새 상담 시작
1. 사용자가 상담 시작 화면 진입
2. 기본 CTA로 `새 상담 시작` 노출
3. 최근 활성 스레드가 있으면 `이전 상담 이어서 하기` 보조 영역 노출
4. 사용자가 새 상담 선택 시 신규 스레드 없이 단발 상담 또는 새 연속 스레드 시작

### 시나리오 3. 유료 사용자가 직전 상담 이어받기
1. 상담 시작 화면 또는 상담 완료 화면 진입
2. 프론트가 최근 활성 스레드 조회
3. 최근 스레드 카드 노출
4. 사용자가 특정 스레드 선택
5. 다음 상담 요청에 `threadId` 포함

### 시나리오 4. 유료 사용자가 다른 주제로 새 상담
1. 프론트가 최근 스레드를 보여주더라도 기본 선택은 `새 상담`
2. 사용자가 종목 또는 질문 주제가 바뀌었다고 판단하면 새 상담 시작
3. 새 상담은 기존 스레드와 분리

### 시나리오 5. 만료된 스레드 재진입
1. 프론트가 스레드 목록 조회
2. 만료된 스레드는 `읽기 전용` 또는 `이어서 불가` 상태로 표시
3. 버튼은 `이 상담 기반으로 새 상담 시작` 또는 `새 상담 시작`으로 대체

## 화면 구성

### 1. 상담 시작 화면
목표:
사용자가 새 상담과 이어받기 중 하나를 쉽게 고르게 한다.

노출 요소:

- 메인 CTA: `새 상담 시작`
- 유료 사용자 전용 보조 영역: `이전 상담 이어서 하기`
- 최근 스레드 목록 최대 3개

스레드 카드 표시 정보:

- 종목명
- 마지막 질문 요약
- 마지막 상담 시각
- 상태 배지: `진행중`, `곧 만료`, `만료`

추천 문구:

- `연속 상담은 같은 흐름을 이어서 질문할 때 사용하세요.`
- `종목이나 고민 주제가 바뀌면 새 상담이 더 정확합니다.`

### 2. 상담 완료 화면
목표:
상담 직후 연속 질문을 자연스럽게 유도한다.

노출 요소:

- `이 상담 이어서 질문하기`
- `새 주제로 다시 상담받기`

추천 노출 조건:

- 유료 사용자일 때만 `이 상담 이어서 질문하기` 노출
- 무료 사용자는 잠금 문구 또는 업셀 문구 노출 가능

### 3. 스레드 목록 화면
목표:
사용자가 기존 연속 상담 흐름을 관리할 수 있게 한다.

노출 요소:

- 활성 스레드 목록
- 만료 스레드 목록
- 각 스레드별 마지막 질문/답변 요약
- `이어서 질문하기`
- `닫기`

MVP에서는 전체 전용 화면 없이 모달/바텀시트로 시작해도 무방하다.

## 프론트 상태 정의

### 스레드 상태
- `OPEN`: 이어받기 가능
- `EXPIRING_SOON`: 이어받기 가능하지만 만료 임박
- `EXPIRED`: 읽기만 가능, 이어받기 불가
- `CLOSED`: 사용자가 종료, 이어받기 불가

주의:
백엔드 실제 상태값은 `OPEN`, `EXPIRED`, `CLOSED`만 두고, `EXPIRING_SOON`은 프론트 계산 상태로 처리해도 된다.

## 추천 UX 규칙

### 기본 선택 규칙
항상 기본 선택은 `새 상담`이다.

이유:

- 실수로 과거 문맥을 붙이는 것을 방지
- 상담 품질 오염 최소화
- 사용자 통제감 유지

### 이어받기 제안 규칙
프론트는 아래 조건일 때만 `이전 상담 이어서 하기`를 적극 노출한다.

1. 유료 사용자
2. 최근 활성 스레드 존재
3. 마지막 활동 후 24시간 이내

추가로 아래 경우는 추천 강도를 높일 수 있다.

1. 같은 종목 재선택
2. 직전 상담 직후 재진입
3. 동일 시나리오 계열 재진입

### 새 상담 권장 문구 노출 기준
아래 경우는 새 상담 권장 안내를 붙인다.

1. 다른 종목 선택
2. 직전 상담과 질문 목적 차이가 큰 경우
3. 마지막 상담 후 시간이 오래 지난 경우

예시 문구:

- `이전 상담과 종목이 달라 새 상담으로 시작하는 것을 권장합니다.`
- `질문 흐름이 달라 보여 새 상담이 더 정확할 수 있습니다.`

## 백엔드 연동 플로우

### 플로우 A. 상담 시작 화면 진입
1. 사용자 구독 상태 조회 또는 보유 상태 사용
2. 유료 사용자면 최근 스레드 목록 조회
3. 활성 스레드가 있으면 보조 영역 렌더링

### 플로우 B. 새 상담 시작
1. 사용자가 `새 상담 시작` 선택
2. 상담 요청에서 `threadId` 없이 호출
3. 백엔드가 단발 상담 또는 신규 스레드 기반 상담 처리

### 플로우 C. 이어받기
1. 사용자가 특정 스레드 선택
2. 상담 요청에 `threadId` 포함
3. 백엔드가 스레드 유효성 검증
4. 성공 시 같은 스레드에 새 턴 추가

### 플로우 D. 만료 스레드 선택
1. 사용자가 만료 스레드 선택
2. 프론트는 직접 이어받기 요청 대신 새 상담 유도
3. 필요하면 `이 스레드 기반으로 새 상담 시작` 옵션 제공

## 예시 화면 카피

### 상담 시작 화면
- 제목: `상담 시작`
- 보조 설명: `새로 상담을 시작하거나, 이전 흐름을 이어서 질문할 수 있습니다.`
- 섹션 제목: `최근 연속 상담`

### 스레드 카드 예시
- `삼성전자`
- `마지막 질문: 지금 분할매수 계속해도 될까?`
- `마지막 상담: 3시간 전`
- 버튼: `이어서 질문하기`

### 만료 상태 예시
- 배지: `만료`
- 안내: `이 스레드는 이어서 질문할 수 없습니다. 새 상담으로 시작해 주세요.`

## 예외 처리

### 유료 권한 상실
1. 기존 스레드는 읽을 수 있음
2. 새 턴 추가는 불가
3. 이어받기 버튼 대신 업셀 문구 노출

### 스레드 검증 실패
예:

- 내 스레드가 아님
- 이미 종료됨
- 만료됨

프론트 처리:

1. 토스트 또는 다이얼로그 노출
2. `새 상담 시작` CTA 제공

## MVP 범위 밖
아래는 이후 확장 대상으로 둔다.

1. 사용자 전체 장기 기억
2. 스레드 자동 병합
3. 유사 질문 자동 추천
4. 스레드 제목 자동 편집
5. 스레드 검색

## 최종 UX 원칙
프론트는 `연속 상담을 쉽게 시작하게 하되, 자동으로 과거 문맥을 붙이지 않는다`를 유지해야 한다.

즉,

- 기본은 새 상담
- 이어받기는 사용자 선택
- 만료와 상태는 명확히 표시
- 다른 주제는 새 상담 권장
