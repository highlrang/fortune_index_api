# Premium Consulting Frontend Flow

## 목적
유료 사용자 전용 `연속 상담 스레드` 기능을 프론트 화면에서 어떻게 노출하고 동작시킬지 정의한다.

이번 개정의 핵심은 아래 두 가지다.

1. 연속 상담은 `Gemini + 자체 스레드 저장` 기준으로 동작한다.
2. 투자 판단 화면에서는 `최신 시세`, `최신 뉴스`, `최신 평균단가` freshness를 사용자가 인지할 수 있어야 한다.

## 제품 개념
연속 상담은 `같은 흐름의 상담을 이어서 질문하는 기능`이다.

중요한 전제:

1. 기본 상담은 항상 `새 상담`
2. 연속 상담은 유료 사용자만 사용 가능
3. 같은 스레드 안에서만 이전 질문/답변 요약을 이어서 사용
4. 다른 종목이나 다른 고민이면 새 상담을 권장
5. 최신성이 중요한 답변은 검색과 시세 조회가 끝난 뒤에만 노출

## 이번 UX 개정 포인트

### 1. 최신 근거 확인 상태를 숨기지 않는다
사용자는 투자 판단이 `최신 근거로 생성되었는지`를 화면에서 확인할 수 있어야 한다.

### 2. stale 데이터일 때 억지로 답변하지 않는다
최신 시세나 뉴스가 없으면 프론트도 `답변 제한` 상태를 그대로 보여줘야 한다.

### 3. 이어받기는 대화 기억 기능이지 숫자 재사용 기능이 아니다
스레드를 이어받아도 평균단가, 수익률, 포지션은 매 요청마다 새로 조회한다는 인식을 주는 것이 좋다.

### 4. 내부적으로는 2단계 처리라는 점을 전제로 한다
백엔드는 먼저 질문을 분류하고 필요한 데이터만 가져온 뒤, 그 다음 최종 답변을 만든다.

즉 내부 흐름은 아래와 같다.

1. 질문 분류/종목 추출
2. 필요 시 KIS/포지션/웹검색 조회
3. 최종 응답 생성

## 주요 사용자 시나리오

### 시나리오 1. 무료 사용자가 상담 시작
1. 사용자가 상담 시작 화면 진입
2. `새 상담 시작`만 노출
3. 연속 상담 관련 UI는 숨기거나 잠금 표시

### 시나리오 2. 유료 사용자가 새 상담 시작
1. 사용자가 상담 시작 화면 진입
2. 기본 CTA로 `새 상담 시작` 노출
3. 최근 활성 스레드가 있으면 `이전 상담 이어서 하기` 보조 영역 노출
4. 사용자가 새 상담 선택 시 새 스레드 또는 단발 상담 시작

### 시나리오 3. 유료 사용자가 직전 상담 이어받기
1. 상담 시작 화면 또는 상담 완료 화면 진입
2. 프론트가 최근 활성 스레드 조회
3. 최근 스레드 카드 노출
4. 사용자가 특정 스레드 선택
5. 다음 상담 요청에 `threadId` 포함
6. 요청 직후 `질문 분석 중` 상태 표시
7. 필요한 경우 `최신 시세 확인 중`, `최신 뉴스 확인 중` 상태 표시
8. freshness 조건 충족 후 답변 렌더링

### 시나리오 4. 유료 사용자가 포지션 기반 질문
예:
- `내 평단 기준으로 더 물타도 돼?`
- `지금 손절 말고 홀딩이 나아?`

흐름:
1. 사용자가 이어받기 또는 새 상담으로 질문
2. 프론트는 서버가 최신 포지션 스냅샷을 다시 읽는다는 전제를 가진다
3. 응답 카드에 `평균단가 기준 시각`을 함께 표시

### 시나리오 5. 만료된 스레드 재진입
1. 프론트가 스레드 목록 조회
2. 만료된 스레드는 `읽기 전용` 또는 `이어서 불가` 상태로 표시
3. 버튼은 `이 상담 기반으로 새 상담 시작` 또는 `새 상담 시작`으로 대체

### 시나리오 6. 최신 뉴스 확보 실패
1. 사용자가 `최근 뉴스 반영해서 알려줘` 같은 질문
2. 서버가 fresh 뉴스 근거 확보 실패
3. 프론트는 일반 답변처럼 보이지 않게 제한 상태를 렌더링
4. CTA는 `다시 시도` 또는 `뉴스 없이 일반 리스크 조언 보기`

## 화면 구성

### 1. 상담 시작 화면
목표:
사용자가 새 상담과 이어받기 중 하나를 쉽게 고르게 한다.

노출 요소:

- 메인 CTA: `새 상담 시작`
- 유료 사용자 전용 보조 영역: `이전 상담 이어서 하기`
- 최근 스레드 목록 최대 3개

스레드 카드 표시 정보:

- 종목명
- 마지막 질문 요약
- 마지막 상담 시각
- 상태 배지: `진행중`, `곧 만료`, `만료`
- 보조 정보: `마지막 근거 갱신 시각`

추천 문구:

- `연속 상담은 같은 흐름을 이어서 질문할 때 사용하세요.`
- `종목이나 고민 주제가 바뀌면 새 상담이 더 정확합니다.`
- `평균단가와 시세는 이어받기 때마다 다시 확인합니다.`

### 2. 상담 진행 화면
목표:
최신 근거 조회와 답변 생성 과정을 사용자가 이해하게 한다.

노출 요소:

- 질문 입력창
- 최근 대화 리스트
- 근거 상태 바

근거 상태 바 예시:

- `질문 분석 중`
- `시세 확인 중`
- `포지션 확인 중`
- `최신 뉴스 검색 중`
- `응답 생성 중`

완료 후 표시 필드:

- `시세 기준: 2026-03-27 10:11`
- `평단 기준: 2026-03-27 10:11`
- `뉴스 기준: 2026-03-27 10:11`
- `출처 3건`

### 3. 상담 완료 화면
목표:
상담 직후 연속 질문을 자연스럽게 유도하되, 답변 freshness를 보여준다.

노출 요소:

- `이 상담 이어서 질문하기`
- `새 주제로 다시 상담받기`
- `이번 답변의 근거`

근거 섹션 예시:

- `실시간 시세 반영`
- `최신 뉴스 반영`
- `내 평단 반영`
- `출처 보기`

### 4. 스레드 목록 화면
목표:
사용자가 기존 연속 상담 흐름을 관리할 수 있게 한다.

노출 요소:

- 활성 스레드 목록
- 만료 스레드 목록
- 각 스레드별 마지막 질문/답변 요약
- 마지막 근거 갱신 시각
- `이어서 질문하기`
- `닫기`

## 프론트 상태 정의

### 스레드 상태
- `OPEN`: 이어받기 가능
- `EXPIRING_SOON`: 이어받기 가능하지만 만료 임박
- `EXPIRED`: 읽기만 가능, 이어받기 불가
- `CLOSED`: 사용자가 종료, 이어받기 불가

### 근거 상태
- `FRESH`: 현재 답변에 최신 근거 사용
- `STALE`: 오래된 근거라 투자 단정 금지
- `UNAVAILABLE`: 근거 조회 실패
- `PARTIAL`: 시세는 fresh지만 뉴스 또는 포지션 일부 누락

### 요청 진행 상태
- `ANALYZING_QUESTION`
- `LOADING_PRICE`
- `LOADING_POSITION`
- `LOADING_NEWS`
- `GENERATING`
- `LIMITED_BY_STALE_DATA`
- `COMPLETED`

## 추천 UX 규칙

### 기본 선택 규칙
항상 기본 선택은 `새 상담`이다.

이유:

- 실수로 과거 문맥을 붙이는 것을 방지
- 상담 품질 오염 최소화
- 사용자 통제감 유지

### 이어받기 제안 규칙
프론트는 아래 조건일 때만 `이전 상담 이어서 하기`를 적극 노출한다.

1. 유료 사용자
2. 최근 활성 스레드 존재
3. 마지막 활동 후 24시간 이내

추가로 아래 경우는 추천 강도를 높일 수 있다.

1. 같은 종목 재선택
2. 직전 상담 직후 재진입
3. 동일 시나리오 계열 재진입

### 새 상담 권장 문구 노출 기준
아래 경우는 새 상담 권장 안내를 붙인다.

1. 다른 종목 선택
2. 직전 상담과 질문 목적 차이가 큰 경우
3. 마지막 상담 후 시간이 오래 지난 경우

예시 문구:

- `이전 상담과 종목이 달라 새 상담으로 시작하는 것을 권장합니다.`
- `질문 흐름이 달라 보여 새 상담이 더 정확할 수 있습니다.`

### stale 차단 UX 규칙
아래 경우는 일반 답변 카드 대신 제한 카드로 표시한다.

1. 실시간 시세 확인 실패
2. 포지션 기반 질문인데 최신 포지션 조회 실패
3. 최신 뉴스가 필요한 질문인데 fresh 뉴스 근거 부족

제한 카드 예시 문구:

- `최신 시세를 확인하지 못해 지금 매수/매도 판단을 단정할 수 없습니다.`
- `최신 뉴스 근거를 확보하지 못해 이슈 기반 해석은 보류했습니다.`
- `평균단가 최신값을 읽지 못해 평단 기준 조언은 제공하지 않습니다.`

## 백엔드 연동 플로우

### 플로우 A. 상담 시작 화면 진입
1. 사용자 구독 상태 조회 또는 보유 상태 사용
2. 유료 사용자면 최근 스레드 목록 조회
3. 활성 스레드가 있으면 보조 영역 렌더링

### 플로우 B. 새 상담 시작
1. 사용자가 `새 상담 시작` 선택
2. 상담 요청에서 `threadId` 없이 호출
3. `stockCode`를 포함해 호출
4. 백엔드가 먼저 질문 분류
5. 필요 데이터만 조회 후 최종 응답 생성

### 플로우 C. 이어받기
1. 사용자가 특정 스레드 선택
2. 상담 요청에 `threadId` 포함
3. 백엔드가 스레드 유효성 검증
4. 백엔드가 질문 분류
5. 시세/포지션/뉴스 fresh 검증 수행
6. 성공 시 같은 스레드에 새 턴 추가

### 플로우 D. 만료 스레드 선택
1. 사용자가 만료 스레드 선택
2. 프론트는 직접 이어받기 요청 대신 새 상담 유도
3. 필요하면 `이 스레드 기반으로 새 상담 시작` 옵션 제공

### 플로우 E. 최신성 제한 응답 수신
1. 응답의 `marketEvidence` 또는 오류 코드 확인
2. `LIMITED_BY_STALE_DATA` 상태 렌더링
3. 재시도 CTA 노출
4. 필요하면 `일반 조언만 보기` 보조 CTA 노출

## 예시 화면 카피

### 상담 시작 화면
- 제목: `상담 시작`
- 보조 설명: `새로 상담을 시작하거나, 이전 흐름을 이어서 질문할 수 있습니다.`
- 섹션 제목: `최근 연속 상담`

### 스레드 카드 예시
- `SK하이닉스`
- `마지막 질문: 주가가 떨어지는데 홀딩이 맞을까?`
- `마지막 상담: 3시간 전`
- `근거 갱신: 2시간 전`
- 버튼: `이어서 질문하기`

### 근거 상태 예시
- 배지: `실시간 시세 반영`
- 배지: `최신 뉴스 반영`
- 배지: `평단 최신 조회 완료`

### 제한 상태 예시
- 배지: `최신 뉴스 미확인`
- 안내: `최신 뉴스 근거가 부족해 이슈 기반 판단은 보류했습니다.`

## 예외 처리

### 유료 권한 상실
1. 기존 스레드는 읽을 수 있음
2. 새 턴 추가는 불가
3. 이어받기 버튼 대신 업셀 문구 노출

### 스레드 검증 실패
예:

- 내 스레드가 아님
- 이미 종료됨
- 만료됨

프론트 처리:

1. 토스트 또는 다이얼로그 노출
2. `새 상담 시작` CTA 제공

### freshness 검증 실패
프론트 처리:

1. 이유를 명확히 표시
2. 시세/뉴스/포지션 중 무엇이 stale인지 구분
3. `다시 시도` CTA 제공
4. stale 값을 화면에 최신값처럼 보이게 표시하지 않음

## MVP 범위 밖
아래는 이후 확장 대상으로 둔다.

1. 사용자 전체 장기 기억
2. 스레드 자동 병합
3. 유사 질문 자동 추천
4. 스레드 검색
5. 출처별 신뢰도 점수 시각화

## 최종 UX 원칙
프론트는 `연속 상담을 쉽게 시작하게 하되, 자동으로 과거 문맥을 붙이지 않고, 최신 근거 없는 투자 단정도 하지 않는다`를 유지해야 한다.

즉,

- 기본은 새 상담
- 이어받기는 사용자 선택
- 숫자 데이터는 매 요청 다시 확인
- 최신 근거 상태는 화면에 표시
- stale 근거면 답변 제한 상태를 숨기지 않음
